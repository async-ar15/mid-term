Module 1 — Digital Image Fundamentals

1. Digital Image

A digital image is a 2-D function of pixel values. Every pixel has a position + an intensity value.

For an 8-bit grayscale image:   0 ≤ f(x, y) ≤ 28 − 1

2. Image Size / Resolution

If we have M × N pixels, then total number of pixels = M ∗ N.

3. Gray Level

The number of possible intensity values is called the number of gray levels. If each pixel uses k bits:

L = 2k

  1. Step 1 — Start with any object / scene.
  2. Step 2 — Sensor converts incoming energy into an electrical signal. e.g. CCD, CMOS.
    • CMOS = Complementary Metal Oxide Semiconductor

7. Image Types & Data Representation

  1. Binary image — each pixel has only 2 possible values: 0, 1.
  2. Grayscale image — each pixel represents intensity. For 8-bit grayscale the range is 0 to 255.
  3. RGB image — has 3 channels / bands, so each pixel has 3 intensity values. For an 8-bit-per-channel image there are 256³ colours; storage = 3 × 8 = 24 bits/pixel.

1. Nearest Neighbour (NN) Interpolation

For a new pixel, simply find the closest existing pixel and copy its intensity. Gives an abrupt change.

Old(r, c) = New( r/2 , c/2 ) = New( round(r/2), round(c/2) ) Generally, if the scaling factor is n:  ( r/n , c/n ) For compression → multiplied by n.

Example: the new pixel at (2,2) maps back to round(1, 1) → value 40.

2. Bilinear Interpolation

Some kind of (weighted) average — gives a gradual change.

Take the four surrounding pixels P11, P12, P21, P22 (brightness values), with r + x and c + y where 0 ≤ x ≤ 1, 0 ≤ y ≤ 1:

P = (1−x)(1−y)·P11 + (1−x)·y·P12 + x(1−y)·P21 + x·y·P22

The weights sum to 1:

(1 − y − x + xy) + (y − xy) + (x − xy) + xy = 1  → it is a weighted average.

Worked example — corner values 10, 20, 30, 40 (P11=10, P12=20, P21=30, P22=40); midpoints come out as 15 (top), 25 (centre), 35 (bottom), 20 (left), 30 (right).

With x = 0.5, y = 0: P = 0.5·P11 + 0.5·P21 = 20.

5 possible positions to interpolate inside one cell: (0.5, 0), (0, 0.5), (1, 0.5), (0.5, 1), (0.5, 0.5).

To go 2 → 4 → 6 (i.e. 3×), repeat the operation.

P = Σi = 0…15 wi · f(x, y)

Uses a 4×4 neighbourhood (16 pixels). Nearer pixels should have higher weights; the weights are IDW (inverse distance weights). Example weight mask used in class:

Module 2 — Image Enhancement / Intensity Transformation

Mainly covers image enhancement, intensity transformation and histogram processing.

Brightness Transformation

Original image: f(x, y), where f(x, y) is the intensity of the pixel. For an 8-bit grayscale image 0 ≤ f(x, y) ≤ 255. To make the entire image brighter:

g(x, y) = f(x, y) + β
Important
  • β positive → image becomes brighter, and the histogram shifts towards the right.
  • β negative → image becomes darker, and the histogram shifts towards the left.

Clipping at the boundary: if f = 240, β = 40 → g = 280 > 255, which is not allowed, so we take g = 255. Same for the other side.

Difference between brightness and contrast: in brightness we are shifting the whole image intensities, not the gap / change of neighbourhood.

Contrast Transformation

In contrast we spread or compress intensities:

g = α · f
  • α > 1 → increases contrast → increase in histogram spread.
  • α < 1 → decreases contrast → decrease in histogram spread.

If α becomes large, many bright pixels can get pushed to 255 (same clipping rule as before), causing saturation and loss of detail.

Binary Thresholding

g(x, y) = { 255,  if f(x, y) > T {   0,  otherwise

Suppose we have a grayscale image — every pixel can have 256 possible intensity values. Suppose we don't care about all those shades and we simply want object → white, background → black. So we use thresholding here: binary thresholding is done for image segmentation.

The choice of T is very important; we can have either:

  1. Foreground extraction
  2. Background removal
  3. Loss of object detail — if T is high we can lose the object
  4. Noise

Gray Level Slicing

Unlike binary thresholding, in gray level slicing we define a range. e.g. 50 ≤ f(x, y) ≤ 150; for this range we either make it white or black:

g(x, y) = { 250,  50 ≤ f(x, y) ≤ 150 {   0,  otherwise

Histogram Stretching

Important The problem: imagine an 8-bit image, where theoretically the intensity range is 0 → 255. But suppose your actual image uses only 50 → 180. So we are not using the full available intensity range; as a result the image looks somewhat low contrast.

Solution: histogram stretching — we fit the range, so 50 → 0 and 180 → 255, done using min–max.

g = (f − rmin) × 255 / (rmax − rmin)

For an arbitrary original min–max target range:

g = gmin + (f − rmin)(gmax − gmin) / (rmax − rmin)
  • f → original value
  • r → original max, min
  • g → desired range

Histogram Stretching + Clipping

min–max fixes the range, but what we mean by clipping here is: let's say the image range is [20, 230] and we want it in [50, 200] — so we clipped the outer darker outliers.

Practically we choose a useful intensity range, clip everything outside it, then stretch that chosen range to 0–255:

g = { 0, f < rmin { (f − rmin)·255 / (rmax − rmin), rmin ≤ f ≤ rmax { 255, f > rmax

Log Transformation

g = c · log(1 + f)

It expands dark pixel values and compresses bright pixel values.

Exponential Transformation

g = c (eαf − 1)

It expands higher intensity values more strongly.

Power Law / Gamma Transformation

g = c · fγ
Important
  • γ = 1 → no transformation.
  • γ < 1 → dark values are expanded → image becomes brighter.
  • γ > 1 → dark values are compressed, higher intensities become relatively more prominent → image becomes darker.

Histogram Equalization

Important Suppose most pixels are concentrated in a small intensity region (e.g. 50 → 120). The image may have poor contrast. Histogram equalization tries to redistribute intensity across a wider range.

Intuition (contrast & variance)

Compare histogram A (peaked) with B (flat, spread to 255). Which has higher contrast? Check in the pixel domain: compare each pixel w.r.t. its 8 neighbours — variance across the image, with all the neighbours. B will have overall higher variance → higher contrast.

Non-linear stretching rule of thumb from the notes:

Where the histogram is thick (mota) → stretch more; where it is thin (patla) → stretch less. If you clip the peak you lose information; stretching a thin region creates problems.

Adaptive Histogram Equalization (AHE)

Normal histogram equalization considers the whole image. Adaptive histogram equalization says: different parts of the image may need different enhancement. So instead of one histogram for the whole range, we divide the image into small regions and equalize them individually.

Contrast Limited Adaptive Histogram Equalization (CLAHE)

CLAHE = AHE + limit on contrast. AHE can sometimes over-amplify noise, especially in nearly uniform areas. CLAHE therefore:

  1. Divide the image into tiles
  2. Calculate the histogram for each tile
  3. Clip at a specified contrast limit
  4. Redistribute the excess
  5. Perform equalization
  6. Combine neighbouring tiles smoothly

Colour preservation

Blindly enhancing individual RGB components can modify colour; converting to grayscale loses colour information.

Important Low Pass Filter → ① allows low frequency info ② suppresses high frequency info.
High Pass Filter → ① allows high frequency info ② suppresses low frequency info.
High pass filters enhance the gap between pixels, hence increasing contrast → edge enhancement & feature extraction.

Frequency = variance, not brightness

  • A homogeneous block (e.g. all values ≈ 200) is a low-frequency zone.
  • A block with large variation (e.g. 20, 03, 32, 66 / 2, 25, 90, 64 / 17, 15, 255) is a high-frequency zone: variance ↑, not homogeneous.
  • Accordingly, high pass filter promotes high-frequency areas; low pass filter promotes low frequency and demotes high frequency.
  • High / low frequency depends upon variance, not brightness.
  • Both zones can exist within the same image.

Correlation vs Convolution

  • Correlation — the process of applying a kernel to an image neighbourhood without flipping the kernel.
  • Convolution — the process of applying a kernel after rotating / flipping it by 180° (horizontally & vertically).

Linear vs Non-Linear Filtering

Linear filter: output is a weighted sum of neighbourhood pixels. e.g. mean filter.

g(x, y) = Σ f(x + i, y + j) · w(i, j)  ← calculates a weighted sum

Non-linear filter: doesn't simply calculate a weighted sum. e.g. median filter.

Take: [10, 20, 200, 30, 40] Sort: [10, 20, 30, 40, 200] Median: 30

Padding, Stride & Output Size

  • Padding — added at the borders so the kernel can be applied at edge pixels.
  • Stride — the step by which the kernel shifts. On an 8×8 input with stride = 2 and a 1×1 convolution convention, the output is 4×4.
  • At borders, a value of 0 in the neighbourhood can be replaced with the local weighted mean, e.g. (200×8 + 0)/9 = 1600/9 = 177.77 → replace 0 by 177.77.
Weighted result = Σ fi wi / Σ wi

Hough Transformation

Important Used to detect geometric shapes in an image — lines, circles, and other shapes that can be represented parametrically.

How it differs from normal edge detection

Let's say we have a broken line. The edge detector says there are 2 edges, but Hough identifies it as a single straight line formation.

Steps

  1. Parametric form of a line:
    ρ = x cos θ + y sin θ
    where ρ = perpendicular distance from the origin to the line, and θ = angle made by the perpendicular with the +ve x-axis.
  2. Suppose we have one edge pixel. Can this pixel belong to many different lines? → Yes. So one image pixel generates many possible (ρ, θ) combinations. These are represented in Hough space.
  3. Now imagine we have many edge pixels belonging to the same line. Each pixel votes for all the possible lines that could pass through it. Eventually the correct line gets the maximum votes. We store the votes in an accumulator array.
    Pixel votes → Accumulator counts → peak tells us the shape

Each point generates its own equation: ρ = x₀cos θ + y₀ sin θ, ρ = x₁cos θ + y₁ sin θ, … , ρ = xncos θ + yn sin θ.

Circles

For a circle we have another parametric representation:

(x − a)² + (y − b)² = r²  (a, b = centre, r = radius)

Therefore it is a 3-D Hough space.

Remember One pixel → one sinusoid in Hough space.
Multiple points → the sinusoids intersect at one common point.
That common point is the line parameter.

In the accumulator drawing, θ runs from −90° to +90° on the x-axis and distance (ρ) on the y-axis; the sinusoids for different edge points are plotted and their crossing gives the detected line.

One-line answers marked "Imp" in the notebook

  • Low pass = allows low frequency, suppresses high frequency. High pass = the opposite; increases contrast → edge enhancement & feature extraction.
  • High / low frequency depends on variance, not brightness.
  • Correlation = convolution for symmetric kernels; different for asymmetric kernels.
  • Mean filter blurs the image because pixels around an edge are also averaged.
  • Median filter ignores outliers → excellent edge preservation.
  • Smoothing = low pass = suppressing high frequency = reducing contrast; always done before edge detection.
  • Sobel = derivative + smoothing → more robust to noise than Prewitt.
  • Gradient points in the direction of maximum intensity increase, perpendicular to the edge.
  • Second derivative asks: how rapidly is the first derivative changing?
  • Laplacian is noise-sensitive → use LoG; zero crossing = where the Laplacian changes sign.
  • β positive → brighter, histogram shifts right; β negative → darker, shifts left.
  • γ < 1 → brighter; γ > 1 → darker.
  • Two different images can have the same histogram — the histogram carries distribution, not spatial location.
  • Boundary = enclosed (joined) edges.
  • Hough: one pixel → one sinusoid; intersecting sinusoids give the line parameters.
